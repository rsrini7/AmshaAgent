### **SR-10: Distributed Resume Lock**
* **File:** `arcclaw-core/.../state/ResumeCoordinationGuard.java`
* **Issue:** Still JVM-local `ConcurrentHashMap`. In multi-node deployment, two pods can race to resume the same session.
* **Fix:** Move to DB-level advisory lock (pattern already exists in `AdvisoryLockPort`). Existing `BatchResumeRaceTest` must pass with DB-backed guard.
* **Invariant:** §3.4, §7.29

### **SR-11: Validate Startup Placeholders**
* **File:** `arcclaw-app/.../config/AppBootstrap.java`
* **Issue:** Uses `"changeme-..."` placeholder strings for API keys. No startup validation to catch unconfigured keys in production.
* **Fix:** Add `@ConfigProperty` validation or Quarkus `@ConfigMapping` with `@WithDefault` + startup health check.

### **SR-12: Replace Broad catch(Exception) with Specific Types**
* **Files:** 20+ locations across `arcclaw-persistence-sqlite`, `arcclaw-channel-telegram`, `arcclaw-tool-playwright`, `arcclaw-core`
* **Issue:** Generic `catch (Exception e)` blocks mask specific failure types, making debugging harder.
* **Fix:** Replace with specific exception types (`SQLException`, `IOException`, `TimeoutException`). Add `@SuppressWarnings` removal where no longer needed.

### **SR-13: UI Message List Virtualization**
* **File:** `arcclaw-ui/src/components/arc-chat-interface.ts`
* **Issue:** `this._messages.map(...)` renders all messages into DOM. No `@lit-labs/virtualizer`.
* **Fix:** Add virtual scrolling – only visible messages in DOM.
* **Invariant:** §21.1

### **SR-14: Cache Rendered Markdown per Message ID**
* **File:** `arcclaw-ui/src/components/arc-chat-interface.ts`
* **Issue:** `_renderMarkdown(text)` calls `marked.parse()` + `DOMPurify.sanitize()` on every render cycle.
* **Fix:** Cache by `messageId` → sanitized HTML. Invalidate on edit only.
