### **MD-1: Decompose AppBootstrap.java (1200 → 3 classes < 400 each)**
* **File:** `arcclaw-app/.../config/AppBootstrap.java` – **1200 lines** (3x checkstyle gate)
* **Issue:** Mixes config registration, startup orchestration, interactive wizard, environment validation.
* **Fix:** Extract `BootstrapOrchestrator` (sequencing), `EnvConfigInitializer` (config loading), `InteractiveSetupWizard` (CLI wizard flow).

### **MD-2: Decompose LangChainReasoningEngine.java (880 → 2-3 classes)**
* **File:** `arcclaw-core/.../agent/reasoning/LangChainReasoningEngine.java` – **880 lines**
* **Issue:** Grew due to structured output + multi-provider routing. Mixes LLM invocation, structured output handling, token counting, provider fallback.
* **Fix:** Extract `StructuredOutputProcessor`, `ProviderFallbackRouter`. Keep engine as orchestration shell.

### **MD-3: Decompose SystemPromptBuilder.java (693 → 2 classes)**
* **File:** `arcclaw-core/.../agent/reasoning/SystemPromptBuilder.java` – **693 lines**
* **Issue:** Per-role prompt specialization caused growth. Mixes section building, role-specific overrides, context injection.
* **Fix:** Extract `RolePromptSection` strategy per role + `PromptSectionBuilder` for shared section logic.

### **MD-4: Decompose SqliteCheckpointStoreAdapter.java (929 → 2-3 classes)**
* **File:** `arcclaw-persistence-sqlite/.../SqliteCheckpointStoreAdapter.java` – **929 lines** (largest file in persistence layer)
* **Issue:** Monolithic adapter mixing CRUD, batch operations, sweep/cleanup, schema migration.
* **Fix:** Extract `CheckpointBatchOperations`, `CheckpointCleanupService`. Keep adapter as delegation facade.

### **MD-5: Trim CheckpointResumeHandler.java (570 → < 400)**
* **File:** `arcclaw-core/.../agent/loop/CheckpointResumeHandler.java` – **570 lines** (checkstyle-suppressed)
* **Issue:** `resumeAfterBatchDecision()` (54 lines), `resumeAfterBatchDecisionSync()` (58 lines), `executePendingTool()` (48 lines) – three long methods.
* **Fix:** Extract `ResumeStrategyDispatcher` – dispatch per checkpoint type (AWAITING_APPROVAL, IN_PROGRESS, etc.).

### **MD-6: Trim EngineStepHandler.java (538 → < 400)**
* **File:** `arcclaw-core/.../agent/loop/EngineStepHandler.java` – **538 lines**
* **Issue:** Recovery hints, JSON guard, rate-limit retry all accreted during P95.

### **MD-7: Trim AgentStateMachineRunner.java (515 → < 400)**

* **Issue:** Still exceeds 400-line gate despite Phase 3 extraction. Loop control + step routing + result dispatch remain coupled.
* **Fix:** Extract `StepDecisionRouter` to handle TOOL/ENGINE/FINISH dispatch. Runner becomes pure loop shell.

### **MD-8: Trim ParallelToolStepExecutor.java (468 → < 400)**

### **MD-9: Decompose PlaywrightPageRunner.java (444 → 2 classes)**
