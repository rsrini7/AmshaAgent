Good set of decompositions. Here are my thoughts on each, ordered by risk and dependency:

## Prioritization Advice

Do these **first** — lowest coupling, safest extractions:

**MD-6, MD-8, MD-9, MD-10** — Pure internal extractions with no cross-module dependencies. The extracted classes stay in the same package and the parent becomes a thin delegator. Zero risk of breaking CDI injection or constructor chains.

Do these **second** — moderate coupling:

**MD-3, MD-4, MD-5** — These touch persistence and prompt-building which have clear seams. `SqliteCheckpointStoreAdapter` is the most mechanical — CRUD/batch/cleanup are already logically separate, just physically co-located.

Do these **last** — highest risk:

**MD-1, MD-2, MD-7** — These involve startup sequencing (`AppBootstrap`), LLM provider routing (`LangChainReasoningEngine`), and the state machine runner which you just modified today. Let the today's changes settle before touching `AgentStateMachineRunner` again.

***

## Per-Item Notes

**MD-1 (AppBootstrap)** — The `InteractiveSetupWizard` extraction is clean. Watch out for `@ConfigProperty` fields — if you split the class, each new class needs its own injection points. Update `application.yaml` and `.env.example` for any new config keys introduced during extraction.

**MD-2 (LangChainReasoningEngine)** — `StructuredOutputProcessor` is a clean seam. `ProviderFallbackRouter` is trickier — it likely holds retry state and rate limit counters. Make sure the fallback router is `@ApplicationScoped` not `@RequestScoped` so retry counters survive across calls.

**MD-3 (SystemPromptBuilder)** — The `RolePromptSection` strategy pattern is the right approach. Use an interface + one implementation per role, CDI-injected as `Instance<RolePromptSection>` iterated by `role.equals()`. Avoids a big `switch` and keeps each role file under 100 lines.

**MD-4 (SqliteCheckpointStoreAdapter)** — `CheckpointCleanupService` should be `@ApplicationScoped` with its own `@Scheduled` if the sweep is time-based. Don't extract the schema migration into a separate class — keep it in the adapter since it must run before any CRUD operation.

**MD-5 (CheckpointResumeHandler)** — `ResumeStrategyDispatcher` should be a plain non-CDI inner class or package-private class — it doesn't need to be a bean, just a strategy holder. Avoid making it `@ApplicationScoped` since it needs access to the handler's injected dependencies.

**MD-6 (EngineStepHandler)** — `RawJsonGuard` is a perfect static utility class — no state, pure transformation. `ResponseRecoveryHintBuilder` can be a `@ApplicationScoped` bean since it may eventually need config properties for hint text.

**MD-7 (AgentStateMachineRunner)** — `StepDecisionRouter` should receive the `StepDecision` and the current context and return the next `AgentState`. Be careful: the pre-flight browser logic you added today lives in this class — don't accidentally lose it during extraction.

**MD-8 (ParallelToolStepExecutor)** — `SequentialToolExecutor` extraction is mechanical. Ensure both paths share the same `WorkspaceContext.run()` wrapper — don't duplicate the context propagation logic.

**MD-9 (PlaywrightPageRunner)** — `NavigationStrategy` holding the wait + fallback chain is clean. The `maps()` method at 85 lines is the main offender — it's really a `PageContentExtractor` concern, not navigation. Consider a third extraction: `PageContentExtractor`.

**MD-10 (PlaywrightBrowserInstaller)** — Easiest of all. `BrowserHealthChecker.isChromiumInstalled()` + `BrowserDownloadService.installChromium()` are already logically separate today. The sentinel file logic you added this morning belongs in `BrowserHealthChecker`.

## Cross-Cutting Reminders

- **`ExceptionUtils.getRootCauseMessage(e)`** everywhere instead of `e.getMessage()` or printing stack traces — already in your standards, just flag it for MD-2's fallback router which will have the most exception paths.
- **Constructor injection only** — no `@Inject` on fields. When splitting classes, every new CDI bean needs a full `@Inject` constructor. Run `mvn compile` after each extraction, not just at the end.
- **`mvn test -pl arcclaw-core`** after MD-5, MD-6, MD-7 specifically — these touch the agent loop which has the most unit test coverage.

Good plan overall. Start with MD-10 today since you're already in `PlaywrightBrowserInstaller` from this morning's sentinel work.
